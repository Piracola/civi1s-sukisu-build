## 编译错误分析

### 1. ext4文件系统错误（高优先级）

**错误**：`ext4_check_dir_entry`宏参数不匹配

```c
// fs/ext4/namei.c:2286
error: too few arguments provided to function-like macro invocation
    if (ext4_check_dir_entry(dir, NULL, de, bh2, data2, len,
                                  bh->b_size, 0) ||
```

**原因**：
- upstream 5.4.302: 宏有更多参数（dir, filp, de, bh, buf, size, lblk, offset）
- 小米代码调用: 参数不够

**影响**：❌ 无法编译，影响ext4文件系统

---

### 2. f2fs文件系统错误（高优先级）

**错误**：`sbi`变量未定义

```c
// fs/f2fs/xattr.c:767
error: use of undeclared identifier 'sbi'
    if (F2FS_OPTION(sbi).fsync_mode == FSYNC_MODE_STRICT)
```

**原因**：
- upstream补丁改变了函数签名或上下文
- 小米代码缺少sbi变量的定义

**影响**：❌ 无法编译，影响f2fs文件系统

---

### 3. SELinux错误（中优先级）

**错误**：`rc`变量未定义

```c
// security/selinux/ss/services.c:2811
error: use of undeclared identifier 'rc'
```

**原因**：
- upstream补丁重构了代码结构
- 小米代码缺少rc变量的声明

**影响**：❌ 无法编译，影响SELinux安全模块

## 具体修复技术

### 手动解决冲突的通用流程

```bash
# 1. 查看reject文件
cat file.c.rej

# 2. 理解冲突
# - upstream想要做什么改动？
# - 小米代码有什么特殊实现？
# - 如何合并两者？

# 4. 测试

# 5. 清理
rm file.c.rej
```
