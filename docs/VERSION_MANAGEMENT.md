# 内核版本管理系统

本文档说明如何使用自动化内核更新和Git版本管理系统。

## 概述

系统提供以下功能：
- ✅ 自动检查Linux 5.4.x最新版本
- ✅ 增量补丁更新内核
- ✅ Git版本标签和分支管理
- ✅ GitHub Actions自动化构建
- ✅ 定期自动检查更新

## 快速开始

### 1. 检查更新

```bash
# 查看当前版本和最新版本
./update-kernel.sh check
```

输出示例：
```
[INFO] Checking for kernel updates...

Current version: 5.4.86
Latest version:  5.4.302

[INFO] Update available: 5.4.86 → 5.4.302

To update, run: ./update-kernel.sh update
```

### 2. 更新内核版本

```bash
# 更新到最新版本
./update-kernel.sh update

# 或指定特定版本
./update-kernel.sh update 5.4.200
```

### 3. 构建内核

```bash
# 使用更新后的源码构建
./build.sh build

# 或完整构建流程
./build.sh full
```

## 命令参考

### update-kernel.sh

| 命令 | 说明 |
|------|------|
| `check` | 检查是否有可用更新（默认命令） |
| `update [version]` | 更新到最新版本或指定版本 |
| `version` | 显示当前内核版本 |
| `latest` | 显示最新的可用版本 |

### version-manager.sh

| 命令 | 说明 |
|------|------|
| `info` | 显示版本信息（默认命令） |
| `list` | 列出所有版本标签 |
| `tag [version] [message]` | 创建版本标签 |
| `branch <version>` | 创建版本分支 |
| `switch <version>` | 切换到指定版本 |
| `push [remote]` | 推送标签到远程 |
| `compare <v1> <v2>` | 比较两个版本 |

## GitHub Actions工作流

### 自动构建 (build.yml)

**触发条件：**
- 推送到main分支
- Pull Request到main分支
- 手动触发

**改进：**
- ✅ 使用ubuntu-22.04（解决无限排队问题）
- ✅ 缓存工具链加速构建
- ✅ 自动创建版本标签
- ✅ 构建失败时上传日志

### 自动更新检查 (auto-update.yml)

**触发条件：**
- 每周一凌晨3点（UTC+8）
- 手动触发

**功能：**
1. 检查最新内核版本
2. 发现更新时创建Issue提醒
3. 手动触发时自动应用更新并创建PR

**手动触发更新：**

1. 进入Actions页面
2. 选择"Auto Update Kernel"工作流
3. 点击"Run workflow"
4. 可选：输入目标版本号
5. 点击"Run workflow"

## 版本管理策略

### Git标签命名

格式：`kernel-v<version>-<date>`

示例：
- `kernel-v5.4.86-20250308`
- `kernel-v5.4.200-20250308`

### 分支策略

- `main` - 主分支，包含最新稳定版本
- `kernel-<version>` - 特定版本分支（可选）

### KERNEL_VERSION文件

文件`KERNEL_VERSION`记录当前内核版本：

```
5.4.86
```

## 更新流程详解

### 1. 版本检查

脚本会：
1. 读取`KERNEL_VERSION`文件或解析`Makefile`
2. 从kernel.org获取最新的5.4.x版本
3. 比较版本号

### 2. 增量补丁应用

对于每个小版本升级（如5.4.86 → 5.4.87）：

1. 下载增量补丁：`patch-5.4.86-87.xz`
2. 应用补丁：`git apply patch-5.4.86-87`
3. 处理冲突（如果有）
4. 更新`Makefile`中的`SUBLEVEL`

### 3. Git提交

自动创建提交：

```
chore: update kernel to 5.4.87

- Applied incremental patches from kernel.org
- Updated SUBLEVEL in Makefile
- Generated by auto-update script
```

### 4. 版本标签

创建注释标签：

```bash
git tag -a kernel-v5.4.87-20250308 -m "Kernel version 5.4.87 - Build 20250308"
```

## 常见问题

### Q: 补丁应用失败怎么办？

A: 脚本会自动尝试`git apply --reject`，生成的`.rej`文件会显示冲突位置。需要：

1. 查看冲突文件：
   ```bash
   cd Xiaomi_Kernel_OpenSource-zijin-s-oss
   find . -name "*.rej"
   ```

2. 手动解决冲突

3. 清理reject文件：
   ```bash
   find . -name "*.rej" -delete
   ```

4. 提交修复：
   ```bash
   git add -A
   git commit -m "fix: resolve patch conflicts for 5.4.87"
   ```

### Q: 如何回退到之前的版本？

A: 使用version-manager切换：

```bash
# 列出所有版本
./version-manager.sh list

# 切换到指定版本
./version-manager.sh switch 5.4.86
```

或直接使用Git：

```bash
git checkout kernel-v5.4.86-20250308
```

### Q: GitHub Actions构建失败？

A: 检查：

1. 查看构建日志（Artifacts中的`build-logs-*`）
2. 本地测试构建：`./build.sh build`
3. 检查内核配置和补丁兼容性

### Q: 如何跳过某些版本更新？

A: 直接指定目标版本：

```bash
# 从5.4.86直接跳到5.4.200
./update-kernel.sh update 5.4.200
```

注意：跳过太多版本可能增加冲突概率。

## 技术细节

### 版本比较算法

脚本使用以下逻辑比较版本：

```bash
# 版本格式：major.minor.sublevel
# 示例：5.4.86

if major相同 && minor相同; then
    if sublevel1 < sublevel2; then
        需要更新
    fi
else
    不同分支，不支持更新
fi
```

